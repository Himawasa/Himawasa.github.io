## 1. 何をしたか・なぜか
岩城さんから「本気で SEO 対策してほしい。問い合わせが来ない」と依頼。10/1 の診断で、スマホ想定の表示速度が Lighthouse 56点、最初の表示まで 8.8秒、いちばん大きな要素（LCP＝トップ画面の説明文）まで 11.3秒と分かった。検索順位と離脱に直結するため、まず速さを直した。
やったこと（本番にはまだ出していない）:
1. ロゴ画像 `public/logo.png` を色数を減らして 246KB→25KB（透明・大きさはそのまま。アイコン・OGP 用）。画面の中の小さなロゴ（24〜80px 表示）用に `public/logo-160.png`（7KB）を作り、Hero・Navbar・BrandStory で使う
2. Web フォントの読み方を「描画を止めない」形に（`<link rel="preload" as="style" onload=...>` ＋ `<noscript>` の控え）。太さを 8種→5種に（Noto Sans JP 400/700/900、Inter 700/900。使っていない 500/600/Inter400 を外した。500/600 の指定は 4か所あり、近い太さで表示される）
3. Google アナリティクスのタグ（174KB）を、画面が出たあと（`load` 後）に読む。`gtag('config')` の呼び方は同じ
4. トップ画面の文字（ロゴ・帯・見出し・説明・ボタン・一言・実績の行）を、`vite.config.js` が `index.html` の `#root` に静的 HTML として埋め込む。文章の元は新しい `src/pages/Home/sections/heroText.js` に1か所化し、`Hero.jsx` もそこを読む。React が起動すると同じ内容に置き換わる。置き換えのときに一瞬消えないよう、Hero の左側の「消えてから現れる」動き（`initial='hidden'`）を `initial={false}` にした（右側のカードの動きはそのまま）
5. 背景の光 `.hero-glow` の `filter: blur(120px)` を外した（もともと radial-gradient で柔らかい。常時動く要素の blur は計算が重い）。`will-change: transform, opacity` を追加

## 5. 白ヤギが自分で気になっている点
- 4 の静的 HTML は Hero.jsx と「同じ class」を手で並べたもの。Hero.jsx の構造を変えたときに、heroText.js の `heroStaticHtml()` を直し忘れると、JS 前と後で見た目がずれる。文章は共有しているが、HTML の形は共有していない
- 静的 HTML には `<a href="/contact">` を使い、React 側は `<Link>`。JS が読み終わる前に押すと、通常の画面遷移になる（動きはするが、SPA の遷移ではない）
- `initial={false}` にしたので、トップ画面の左側は「ふわっと現れる」動きがなくなった。見た目の方針として岩城さんが気にするかもしれない
- 「操作できるまで 11.4秒」「固まり 1,410ms」は残っている。原因は JS 本体（402KB。react・framer-motion・全セクション）と、常時動く部品（粒の背景 40個の RAF・1字ずつ出る見出し・光の動き）。これは次の作業（部品の遅延読み込み・動きの間引き）で扱う予定で、今回は触っていない
- Lighthouse の数値は手元の preview のもので、回ごとに ±5点くらいぶれる
