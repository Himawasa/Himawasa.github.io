そもそも何がしたいの？

デライトさんの悩みはシンプルです。

😫 顧問先ごとにバラバラな形式の賃金データを、毎月手作業でシャルフに入力している。
これが大変。時間がかかる。ミスもある。新人に教えるのも難しい。

これを自動化するのが今回のお仕事です。

🎯 ゴール：どんな形式の賃金データでも、ボタン1つでシャルフに取り込めるCSVにする。

3

シャルフに入れる項目は「たった10個」

シャルフのテンプレートは全部で54列ありますが、
東さんが検証した結果、必要なのは10項目だけでした。

# シャルフの項目名 何のデータ？ 変換方法
1個人コード従業員の番号コピー
2氏名従業員の名前コピー
3支給月度何月分の給与か手入力
4給与支給日支給した日コピー or 手入力
5労働日数出勤した日数コピー
6有給休暇日数有給を使った日数コピー
7休日労働日数休日に出勤した日数コピー or 合算
8特別休暇日数慶弔休暇などコピー
9欠勤日数欠勤した日数コピー
10支給総額いくらもらったかコピー
⚡ 基本給も、手当も、控除も全部不要！
なぜ？→ 控除（健康保険、厚生年金など）はシャルフ側で計算するから。
つまり「この人は何日出勤して、いくらもらった」だけわかればOK。

東さんから届いた4つのサンプル

東さんが「基本形」として送ってくれたデータは4つ。
実は2パターンしかありません。

📊 給与奉行（2社分）

  • ALC社：97列、404人分
  • MRS社：238列、148人分
  • 形式：CSV（テキストファイル）
  • 構造：縦並び（1行＝1人）

📊 弥生給与（2社分）

  • KAG社：73行、約40人分
  • NZK社（サイズ小さめ）
  • 形式：Excel（.xlsx）
  • 構造：横並び（1列＝1人）
5

「縦並び」と「横並び」の違い

これが今回の一番大事なポイントです。

🟢 給与奉行 = 縦並び（簡単！）
社員番号, 氏名,   出勤日数, 支給総額
───────────────────────────
   5,   田中太郎,   20,    208881
  24,   鈴木花子,   20,    373984
  26,   佐藤一郎,   20,    481931
  38,   山田次郎,   20,    311589

→ 1行が1人。上から順に読めばOK。
→ Excelで見ても普通の表と同じ。
🟡 弥生給与 = 横並び（ちょっと特殊）
              田中  鈴木  佐藤  山田
─────────────────────────────
出勤日数 →    19    17    19    17
有休日数 →     0     1     0     1
支給合計 → 641554 512340 580000 ...

→ 1列が1人。行と列が逆！
→ プログラムで「縦に倒す」処理が必要。
💡 やることは同じ。
どちらも最終的に「1人1行」の形にして、必要な10項目を抜き出すだけ。
弥生は最初に「横→縦」に変換する工程が1つ増えるだけです。
6

JSONファイルって何？

JSONは「設定ファイル」です。プログラムではありません。

🔧 convert.py（プログラム本体）

「データを読んで、変換して、CSVに出す」という処理の手順が書いてある。
ここは変更しない。

📋 JSON（設定ファイル）

「出勤日数 → 労働日数にコピーする」のような変換ルールが書いてある。
顧問先ごとに1つ作る。

たとえばこんな感じ：

給与奉行ALC用のJSON（一部）
{
  "労働日数": {
    "元の列名": "出勤日数",
    "変換方法": "そのままコピー"
  },
  "支給総額": {
    "元の列名": "総支給金額",
    "変換方法": "そのままコピー"
  }
}
弥生給与KAG用のJSON（一部）
{
  "労働日数": {
    "元の列名": "出勤日数",
    "変換方法": "そのままコピー"
  },
  "支給総額": {
    "元の列名": "支給合計",
    "変換方法": "そのままコピー"
  }
}
💡 違いは「元の列名」だけ！ 給与奉行では「総支給金額」、弥生では「支給合計」。
こういう名前の違いをJSONで吸収しています。
7

なぜ「基本形」から始めるの？

東さんの判断です。最初に送ってくれた5パターンにはPDFが含まれていましたが、 あれはイレギュラー（難易度高い）でした。

✅ 基本形（今回やる）

  • 給与奉行のCSV出力
  • 弥生給与のExcel出力
  • データが整っている
  • 列名がハッキリしている
  • 顧問先の大半がこのパターン

⏳ イレギュラー（後回し）

  • 画像PDF（OCRが必要）
  • テキストPDF（解析が必要）
  • TKC出力PDF
  • データがバラバラ
  • まず基本形を固めてから
🎯 東さんの戦略：基本形で8割の顧問先をカバー → 残り2割は後から対応
賢い判断です。まず効果が大きいところから。
